# MV3 登录态集成验收 — 验证层级与用户检查单（R3-R 更新，PoC v4）

## 验证层级（R3-R P0-D1 口径）

本轮起，所有验证结论必须标注所处层级。**低层级的通过不得升格为高层级的通过。**

| 层级 | 内容 | 当前状态 | 证据位置 |
|---|---|---|---|
| L1 静态源码审查 | 源码逐行审读（无 fetch/XHR、无凭据捕获、无请求重放、权限最小化） | **已完成**（每轮复审） | `exploration-poc/mv3-poc/content.js`（v4）；r3-r-fix-report.md §G1 |
| L2 Node/DOM fixture 测试 | 真实源码离线执行：竞态 10 场景、提取正确性、反例语义、普查分类器与复算 | **已完成 45/45**（`npm run test:r3-r`） | `exploration-poc/r3-r/tests/`；r3-r-race-tests.md |
| L3 CDP 隔离世界注入 | 真实登录会话中以 CDP `Page.addScriptToEvaluateOnNewDocument` 注入等效内容脚本 | **已完成**（R2 十场景 + R3 回归 + R3-R 六窗口 `pane=true`，网络普查 18 窗口） | r3-network-audit.md；r3-r-network-audit.md |
| L4 真实浏览器加载 MV3 扩展 | chrome://extensions 加载 `dist-extension`/mv3-poc 目录后的真实扩展运行时 | **NOT_TESTED**（环境受限：Chrome 155 起移除 `--load-extension`；ego-browser 不开放 `Extensions.loadUnpacked`，已留档） | 本文件检查单 |
| L5 真实登录态端到端交互（含写入） | 用户亲手在真实扩展中执行交互，包括唯一一项写入（第 11 项） | **NOT_TESTED**（由用户决定是否执行） | 本文件检查单 |

> L3 与 L4 的本质差异：L3 的注入发生在**页面会话层**（无 MV3 service worker、无真实 content script 注册管线、无扩展权限模型参与）；它能证明内容脚本逻辑正确，不能证明扩展装载链路正确。两者不可互替。

**R3-R 明确保留的结论**：截至本轮，L4/L5 全部 NOT_TESTED。这不阻塞其余修复任务，但在用户执行检查单之前，"真实扩展运行验证"一项保持未验证状态，不伪造通过。

## 关于 PoC v4（R3-R）

PoC 已升级至 v4（`exploration-poc/mv3-poc/`，manifest 0.3.0 → 0.4.0）：修复了异步构建与路由切换的过期挂载竞态（离开详情页/快速切帖/关闭后旧任务立即失效）、增加了 DOM 等待超时后的有界恢复、修正了互动计数与引用帖媒体的结构化提取。你手上的检查单无需变化，另增第 13 项（快速连点两帖，验证竞态修复）。

## 步骤（在你的 Chrome 中，使用独立 profile，不影响日常配置）

1. 打开 Chrome，进入个人资料选择器（右上角头像 →「添加」），**新建一个 Chrome profile**（名字随意，如 "peek-test"）。这是隔离配置，不触碰你日常 profile。
2. 在新 profile 中打开 https://x.com 并**你自己登录** X 账号（Agent 全程不接触凭据）。
3. 打开 `chrome://extensions/` → 开启右上角「开发者模式」→「加载已解压的扩展程序」→ 选择本仓库的 `exploration-poc/mv3-poc/` 目录。
4. 回到已登录的 X 标签页，按下面的检查单逐项验证（除第 11 项由你亲手操作外均为只读，不需要点赞/回复/关注）。
