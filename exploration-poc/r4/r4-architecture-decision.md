## 2. 最终判定：**CONDITIONAL GO**

**不是 GO**，因为以下两项未闭环：

1. **真实 MV3 验证（G5）未执行**——L4/L5 仍 NOT_TESTED。GO 的必要条件"真实扩展验证
   通过"尚不满足；CDP 等效注入（L3）不能替代扩展装载链路验证。
2. **T2 容差字面 FAIL**——评论首读比原版慢 0.7-1.3s（中位），超出 `max(100ms, 10%)`
   容差。根因是架构性的：R1 的评论区=裸 X 的评论区（实测与原生同分布 2013-2290 vs
   1996-2029），原版的优势来自它自己的 GraphQL 重放 + 自绘渲染管线——恰是 R1 要移除的
   私有接口依赖。**这不是可以在禁令内优化的缺陷，而是方向性取舍**，必须由用户裁决。

**不是 NO-GO**，因为所有 NO-GO 触发条件均不成立：

- 首显明显变慢？**否——反转：R1 快 7-16 倍**（统一口径后原版正文首显 584-1333ms，
  R1 78-84ms；"原版 98ms"是骨架不是内容）。
- 评论阅读明显变慢？**是（0.7-1.3s），但有明确解释与上限**（=裸 X 节奏；数据 350ms
  即在页面内，X 自己选择渐进渲染；R1 无合法手段干预），且不随使用劣化——属用户
  决策项而非无解技术问题。
- 关闭返回明显延迟/闪烁？**否**——中位差 +45~94ms（两样本越线 3-14ms，在 25ms 采样
  量化内），无白屏无闪烁，锚点行为=裸 X。
- 重要功能不可接受地退化？**否**——83 项行不减，PARTIAL 维持 7 项且全部明示。
- 真实扩展关键稳定性缺陷？**未知**——正是 L4/L5 待验项，不伪造结论。

## 3. 给用户的两个决策点

1. **T2 取舍**：接受"评论区以裸 X 的原生节奏出现（比原版慢 0.7-1.3s，焦点帖快
   7-16 倍、零私有 API 重放）"，还是保留原版浮层架构以换取评论首读速度？
   （中间路线不存在：更快评论区⇒必须重放私有 API⇒回到原版架构。）
2. **MV3 人工验收**：执行 `MV3-MANUAL-CHECKLIST-R4.md`（15 项，约 10 分钟，唯一写入项
   可跳过）。回填后本报告升级：全部通过 ⇒ 可改判 **GO** 并启动正式工程第一包。

## 4. CONDITIONAL GO 期间明确禁止的事

- 不得视为"自动获准全面替换原版"；正式 `extension/` 保持不动（本轮已遵守，diff 为空）。
- 不得在未回填 MV3 检查单前开始正式工程第一包的合并/发布动作。
- T2 若被用户否决，按性能 NO-GO 处置（见 §5）。

## 5. 若 T2 被否决（性能 NO-GO 的回退路径）

回到**原版浮层架构**作为正式产品基线，并以其为范围减少私有 API 依赖（不牺牲速度）：

1. 保留浮层 UI 与交互（用户已验收的体验），仅审计 `page-bridge.js` 的重放面：
   只重放"读取焦点帖+评论"所必需的最小 GraphQL 操作集（现行为已是动态发现、
   无硬编码 queryId、凭据不落盘——R1-R3 已验证），去除非必要操作的重放。
2. 吸收 R4 的可用成果（与浮层架构正交）：G0-C 严格网络判定器、点击对齐普查 harness、
   Esc 捕获语义、长帖"折叠首显+原地升级"的提取模式。
3. R1 线归档为"零私有 API 依赖"的长期方向，等待 X 原生详情页的评论渲染节奏
   （裸 X 自身）在真实使用中被用户接受，再重启迁移。

## 6. 若两个决策点均通过（预期路径）

按任务书第十节执行正式工程第一包（上限范围）：数据承载适配层、路由与生命周期模块、
新旧实现切换开关、最小构建与回归测试、明确回退路径——不删除 `page-bridge.js`、原版
UI、原版测试或任何既有功能。本轮已产出可复用的起点：`mv3-poc/content.js`（v5，含
导航轨迹/事件驱动路由/解耦升级）与 73 项离线测试。
