# R4 G1/G2 性能对比：原版 Peek 0.8.10 vs R1 PoC v5 vs X 原生

日期：2026-10-12。分支 `exp/r1-performance-experience-gate`（PoC 0.5.0，含 G2 两轮优化）。

## 1. 方法（为公平性做的关键设计）

- **比较对象**：A = 原版 Peek 0.8.10（`dist-extension/` 构建产物，CDP 按真实扩展的
  manifest 顺序注入：page-bridge MAIN world + vendor/core/content isolated world +
  CSS）；B = R1 PoC v5（`exploration-poc/mv3-poc/`，isolated world）；C = X 原生（无注入，
  仅作参考，不参与等价判定）。三种条件均为 CDP 等效注入（MV3-LOGIN-VERIFY.md 的 L3
  层级）——本环境无法加载真实 MV3 扩展（Chrome 152 ego 会话不开放 loadUnpacked），
  两两之间相对公平；绝对值与真实扩展可能有常量级差异。
- **同一登录会话、同浏览器、同账号、同视口（1440×900）**，三页面交错轮换条件顺序
  消除会话演化偏差；测量窗口把被测页置于前台（后台节流会破坏计时）。
- **统一起点 = 用户真实点击**：CDP `Input.dispatchMouseEvent` 可信点击样本帖的时间戳
  链接；页面内录制器（25ms 采样）记录点击时刻、Esc 时刻、首显谓词达成时刻——所有
  指标减去真实点击时刻，无 CDP 往返噪声。
- **T1 判定**：焦点身份（作者/handle）+ 非空正文 + 面板 ID 与 URL 一致（R1）；
  **骨架屏不算**（原版首帧实测为"正在加载原帖"骨架，见截图
  `evidence/experience/e3-orig-A.png`，其正文首显要等自己的 GraphQL 响应渲染）。
- **T2 判定**：首个带真实归属的实际评论可读（原版=浮层回复卡带时间戳；R1/原生=
  焦点格之外的首个有文本的评论格）。两条件概念一致。
- **T4 判定**：Esc → 信息流可继续滚动/点击（R1/原生：路由离开详情 + 被点击帖单元格
  重新挂载 + 滚动位置稳定；原版：浮层移除 + 滚动稳定）。含锚点恢复检查：X 的后退
  重新锚定虚拟列表（绝对 scrollY 不同），以**被点击帖的视口相对位置**偏差 ≤60px 为恢复。
- **样本**：4 类公开帖（短帖 / 282 回复高回复帖 / Premium"显示更多"长帖 / 视频帖）
  × 3 轮 × 3 条件 = 36 窗口，零跳过零错误；小 n 不算 p95，报原始值/中位数/最慢。
- **反区分性保障**：不减少评论、不停止分页、不删功能换取速度；两轮优化后重跑全套。

\* 原生条件的 T4 含 harness 固有 +300ms 脚本延迟（Esc 后 evaluate 触发后退），仅作参考，
不参与判定；该常数主导了原生侧读数，不据此推导倍数结论（独立 Reviewer 意见已采纳）。

辅助指标：

- **路由识别延迟（G0-B）**：点击 → R1 识别路由 = 中位 **1ms**、最慢 2ms（Navigation API
  事件即时；轮询仅为兜底）。
- **锚点恢复偏差**：原版 0px（页面从未离开）；R1/原生一致 151-153px（X 后退重新锚定
  虚拟列表的自身行为，R1 与裸 X 完全相同）。
- **长任务**（同脚本滚动窗口内）：原版 0-1 次/57ms，R1 1-3 次/72-183ms，原生 1-4 次/
  69-234ms——同一量级，无原版不存在的滚动卡顿。
- **视频起播**（滚动入视口 → playing）：R1 3-17ms vs 原生 24-31ms（信息性；R1 右栏
  即原生播放器，更快是因为面板 CSS 下焦点格更早进入视口）。
- **T3 交互面**：原版浮层回复工具行在位；R1 面板动作行 + 原生编辑器/原生动作条在位；
  均无需额外操作步骤（证据 `t3` 字段，36/36 窗口）。

## 3. G2 两轮优化（均已提交并重测）

1. **第一轮：焦点帖首显与"显示更多"展开解耦**。v4 的构建内联等待 Premium 展开
   （+700ms），长帖 T1 曾达 1234ms。改为：先以折叠正文（X 自己此刻显示的准确内容）
   即时上屏，展开点击一次后**原地**升级全文（不重挂、不闪烁）。长帖 T1 1234→84ms。
2. **第二轮：信息流 DOM 复用 + 详情水合刷新**。G2 第一轮移除展开等待后，构建循环的
   第 0 次尝试直接从**信息流中该帖自己的单元格**提取并首显（任务书明确允许的
   "点击时复用当前信息流已经显示的 DOM 数据"），T1 全样本降到 76-89ms。配套两项
   正确性保障：
   - 焦点格匹配收紧（时间链接不得位于引用卡内，防止"引用了该帖的格子"被误用——
     回归测试在案）；
   - **详情水合后就地刷新**：X 把详情页自己的焦点格换上来后，刷新绝对时间/精确计数/
     媒体/引用块（实测：书签"未知"→1,148、相对时间→绝对时间，无重挂）。
3. 另发现并修复：Esc 关闭监听从冒泡改为**捕获阶段**并阻止传播——X 的全局快捷键管理器
   会拦截 Escape（实测连续第二次 Esc 在冒泡阶段永远收不到）；真实扩展中捕获监听先于
   页面处理器，`stopImmediatePropagation` 同时防止与 X 各自后退一次的双跳。

## 4. 判定解读

- **T1（硬门槛的核心）**：R1 在全部样本**大幅快于原版**（快 7-16 倍，78-84ms vs
  584-1333ms）。此前"原版约 98ms"的口径实为浮层骨架出现时间（本轮实测骨架 55-88ms，
  与其一致）；按统一的"首个有意义内容可读"口径，原版正文首显 584-1333ms。**此前
  "R1 首显 896ms vs 原版 98ms"的担忧经统一口径 + 两轮优化后反转。**
- **T2（本轮唯一的实质差距）**：R1 比 T2 容差慢 684-1268ms。根因是**架构性的**：
  R1 的评论面就是 X 原生详情页自身，评论渲染节奏 = 裸 X 的节奏（R1 1996-2029 vs
  原生 2013-2290，同一分布；R1 的评论数据与焦点帖同在 X 自己 350ms 左右就返回的
  TweetDetail 响应里，X 原生页选择渐进渲染）。原版更快是因为它用自己的 React 树
  一次性渲染自己的 GraphQL 重放结果——那正是 R1 要移除的私有接口依赖。在不重新引入
  私有 API 重放、不克隆/移动 X 实时 DOM 的前提下，**评论首读时间不可能快于裸 X**。
  G2 两轮优化对 T2 无合法手段（已确认无第三轮）。
- **T4**：中位差 +45~94ms，其中两样本越线 3-14ms。R1 的关闭 = 即时面板拆除 + X 自己的
  后退 traverse（+锚点重挂载）；原版的关闭 = 浮层 display 移除（信息流从未离开）。
  这是"关闭后回到何处"的结构差异：R1 回到原生信息流（与裸 X 完全一致），原版根本
  没离开过。越线的 3-14ms 在 25ms 采样量化与波动范围内，但按容差字面如实记 FAIL。
- **波动与 INCONCLUSIVE**：本轮无 INCONCLUSIVE 判定；`evidence/perf-comparison.md` 的
  生成器在原版轮间波动过大时会自动降级该格（此前轮次的 highReply/T2 曾触发）。

## 5. 数据完整性说明（如实记录）

- **早期轮次数字的证据层级**：报告引用的早期轮数字（长帖 T1 曾 1234ms、前轮
  highReply/T2 曾触发 INCONCLUSIVE、骨架 55-88ms、G0-B 首轮 8 窗口）来自已被后续轮次
  覆盖的证据目录，无法从当前 evidence/ 独立复验，其依据是 git 提交历史与运行日志
  （Reviewer 记为 P3-1，如实留档）；**final 轮全部数字可由 `evidence/perf/` 独立复算**。

- **long 样本原版 T2 MISSING**：3 轮中原版浮层在该长帖上焦点正文渲染了（T1 有值），
  但回复卡始终未出现（其网络含 2 次 TweetDetail——重放发生，解析后回复面未渲染）。
  属原版侧的测量缺口，无法归因 R1；该格如实 MISSING，不参与判定。
- **原版点击偶发**：体验脚本与早期基准轮中，原版浮层约 1/3 的特定点击未打开（时间线
  在找帖与点击之间位移，点击落空）。基准以"点击后验证 + 一次重试"吸收；体验脚本侧
  已如实记录（真实使用中未复现该形态，R1-R3 亦未见）。R1 侧无此现象。
- **点击对齐**：基准窗口在网络记录前先"找帖→排空至安静→再点击"，所有记录均为
  点击后流量；网络面判定见 §6 与 `evidence/network-judgment.md`。
