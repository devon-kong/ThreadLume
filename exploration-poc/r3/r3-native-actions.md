# R3 原生互动方式、合成事件差异与剩余风险

日期：2026-10-12。约束：本轮 **0 次真实账号写入**；所有验证限于识别原生控件、检查可见性/定位/焦点、打开不提交的原生界面、只读 UI 探索。写入端到端验收全部留待用户亲手执行（检查单：`exploration-poc/MV3-LOGIN-VERIFY.md` 第 11 项）。

## 1. 三类交互的判定结果

| 类别 | 定义 | R1 结论 |
|---|---|---|
| **A. 用户亲自点击原生控件** | 原生 React 元素接收真实交互 | **R1 的正式路线**。v3 起 PoC 不含任何合成写入委托；每一项互动都有明确的 A 类路径 |
| B. Peek 调用原生控件 `.click()` | 程序合成事件（isTrusted=false） | **已从 PoC 移除**。v2 的互动镜像条曾用合成委托（第 3 类自动化）；R3 判定其不应作为正式方案（见 §3） |
| C. Peek 自行构造接口请求 | 原版内部接口写入路线 | 本轮未执行、保留为对照；R1 下无存在必要 |

## 3. 合成事件（B 类）的正式判定：不采用

v2 PoC 的面板镜像按钮曾对隐藏的原生按钮执行 `native.click()`。R3 实测暴露的连锁问题使该方案被整体替换：

1. **控件不可达**：v2 隐藏焦点格后，原帖操作条、悬浮卡入口、回复框全部不可见不可点——合成委托不是"让用户少一步"，而是"用户没有原生路径可走"。
2. **隐藏本身有缺陷**：富媒体检测竞态 + 轮询重标记覆盖（R3 实锤，见 r3-exploration-report.md §2），会把含视频/卡片的原帖格错误隐藏。
3. **平台规则敏感性**：合成事件属程序化交互。虽然 X 的 React 事件系统通常接受 `isTrusted=false` 点击，但平台对自动化行为的判定属于其规则范畴——A 类路径既然完整存在，就没有理由保留 B 类写入。

v3 替代设计：面板互动按钮 = **定位 + 高亮**（scrollIntoView + 1.6s 描边脉冲），写入由用户亲手在原生控件上完成；"显示更多"一次性显示展开（非账号写入）是 PoC 中唯一的程序化点击，性质等同用户阅读动作。

## 4. 剩余风险与未验收项

| 项 | 状态 | 说明 |
|---|---|---|
| 端到端写入（赞/转/藏/关注/回复） | NOT_TESTED | 全部留待用户真人执行；A 类路径已逐项实测存在 |
| 收藏夹分类/管理页跳转 | NOT_TESTED | 需先真实收藏才能探索入口；原生流程由 X 保证 |
| 私密账号"待批准"关注态 | NOT_TESTED | 无私密目标样本 |
| 回复后置顶展示 | NOT_TESTED | 需真实回复 |
| 合成事件稳定性/平台规则 | 不适用 | B 类已从正式方案移除；若未来任何功能重新引入，必须单独立项评估 |
| Hover 卡触发条件 | 行为差异 | X 悬停意图判定要求真实指针轨迹（单点瞬移不触发出卡，R3 实测）——自动化验收需模拟移动轨迹，真人无感 |

## 5. 与原版 Peek 的损失清单（互动维度）

- 原版浮层内互动（1 步）：R1 同样 1 步（原生控件就在右栏原帖/评论上）。
- 原版纯文字回复无计数器：R1 用原生编辑器，同样无 Peek 强加限制。
- 原版"AI 草稿接口"（离线 4/4 已验证的 draft-only 契约）：R1 下草稿要进入原生编辑器需用户粘贴（接口仍在，注入路径待正式工程设计）——如实记录为待设计项，非架构阻塞。
