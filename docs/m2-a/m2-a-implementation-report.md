## 用户可见行为

左栏维持阅读副本，右栏维持 X 原生 DOM。只有详情 DOM 已出现、紧邻的可读帖子候选可确认、焦点格 ≥60% 视口、下方阅读区域不足50%、用户未操作时，才在6秒内尝试一次定位。原生控件不移动、不隐藏；用户可上滚或点击左栏“定位”回到原生互动区。

候选识别仅依赖原生详情 DOM 结构：焦点格的详情编辑器标记、同一虚拟列表、帖子自有数字 status 时间链接、可读正文或媒体。仅跳过零高度且无文本/语义元素的空分隔格；未知模块、推荐标题、广告、跨列表、只有引用身份的帖子均不能作为定位目标。没有详情标记或无法确认时保留原生滚动。该规则不是 GraphQL 父子关系证明，也不重新渲染或过滤 X 的评论列表。

富媒体在滚动前复查；滚动后最多15秒等待迟到媒体。用户输入立即永久取消回看，即使坐标没有变化或后来回到原位。未操作且迟到媒体出现时，最多回到原生顶部一次；超时、离开路由、拆除或返回均清理计时器与监听。

## 独立评审后的实际修复

| 问题 | 修复与回归证据 |
|---|---|
| 迟到媒体回看已拆输入监听，用户点击/输入后仍被拉回顶部 | 回看阶段重新保持输入守卫；C-12 先失败后通过，覆盖四种输入及回原坐标 |
| 任意下一区块被当成评论，包含空白、编辑器、推荐模块 | 验证详情与候选结构；C-13/C-15/C-16 覆盖空分隔、未知模块、广告、跨列表、非cell标题、引用身份等 |
| 迟到 Article 未在富媒体检查内，左栏也可能没有全文 | 滚动前后识别 Article 标题/正文；C-14 先失败后通过；保留右栏承载，不伪称同cell左栏水合已补齐 |
| URL先变化、旧信息流DOM尚未替换时可能定位普通帖子 | 要求焦点格存在原生详情编辑器标记；C-17 先失败后通过，再验证详情出现后可正常定位 |
