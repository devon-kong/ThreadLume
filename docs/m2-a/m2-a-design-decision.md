# M2-A 设计决策 — 双栏阅读体验第一包（重复焦点帖与评论优先）

分支：`feat/peek-native-m2a-reading`（基于 M1-R `dfb94f7`）
结论：**方案 C（混合门控）** — 简单帖评论优先滚动，富媒体帖保留原生焦点格。

## B0 问题量化（真实 X 实测，1440×900 视口）

阅读器打开时，右栏顶部是 X 原生焦点帖（完整复制左栏已提取的阅读副本），评论被推到折叠线以下：

| 样本 | 原生焦点帖高度 | 占视口 | 打开时评论可见份额 |
|---|---|---|---|
| 纯文本帖（gefei55/2109450990575611958） | 538px | 72% | **21–25%** |
| 图片帖（KinGao476942/2109792240776421482） | 1042px | 132% | **0%** |
| 视频帖（thinkszyg/2109309251533570509） | 1043px | 132% | **0%** |

纯文本帖的 72% 右栏空间与左栏内容完全重复（该帖无任何左栏无法承载的功能）。这是结构性阅读效率损失，不是渲染缺陷。

## B1 三方案最小原型对照（真实 X 实验）

### 方案 A：原生焦点帖 CSS 紧凑化 — 拒绝（证据充分）

在真实 X 上对焦点帖 article 施加 `max-height: 40vh + overflow: hidden` 实验：

- 焦点格 538px → 402px，评论可见份额仅 **21% → 25%（+4%）**。
- 增益微小的结构性原因：焦点格除 article 外还有作者头、原生编辑器、操作栏（约 130px+），clamp article 无法触及；要显著提升必须 clamp 整格。
- clamp 整格 = 编辑器/操作栏在视觉上被裁切、实际不可操作 = "功能名义上存在、实际上不可操作"，触碰任务硬约束。
- 另需对 X 内部结构施加高优先级覆盖（B3 任务明确警告脆弱性）。

### 方案 B：评论优先（全部帖子右栏直接从评论开始）— 机制可行但门控必要

机制原型在真实 X 上验证：挂载后一次 `scrollTo` 把第一条回复带到右栏顶部：

- 稳定性：2 秒后位置保持（X 虚拟列表不反扑），焦点格保留在 DOM（React 状态完好）。
- 回复可见份额 **25% → 100%**。
- 但对视频/投票/卡片/文章帖：打开即滚过原生承载区 = 左栏无法提供播放、投票、原生渲染，功能被"藏起来"。

### 方案 C：混合门控 — 采纳

按内容类型分工：**左栏能完整承载的帖子（文本/图片/引用）评论优先；需要原生承载的帖子（视频/投票/网站卡片/X Article）保持原生焦点格在视野内**。与既有 rich-note 提示（"右栏顶部原生格完整承载媒体与互动"）语义一致。

### 对照记录表

| 指标 | A（紧凑化） | B（全量评论优先） | C（混合门控，采纳） |
|---|---|---|---|
| 原帖阅读完整性 | 裁切即缺失 | 完整（左栏） | 完整（左栏） |
| 评论首屏有效面积 | 21%→25% | 25%→100% | 简单帖 25%→93–100%；富媒体帖维持原生 |
| 原生互动可达性 | 被裁切部分不可操作 | 一次上滚/定位按钮 | 简单帖一次上滚/定位按钮；富媒体帖原位 |
| 富媒体完整性 | 受损风险 | 视频被滚出视野 | 富媒体帖原位保留 |
| 双栏独立滚动 | 不变 | 不变 | 不变 |
| 布局稳定性 | 与 X CSS 竞争（脆弱） | 实测稳定（虚拟列表不反扑） | 同 B（同一机制） |
| 首显性能 | 高优先级 CSS 解析 | 挂载后一次滚动（零 T1 影响） | 同 B + 少量门控判断 |
| 额外操作步骤 | 0（但功能缺失） | 互动需一次上滚 | 同 B，仅限简单帖的互动路径 |

## C 方案的实施语义（B2）

`native-extension/src/comments-first.js`，挂载后武装、每次决策可审计：

1. **门**：提取时 rich 标记（video/poll/card/article 任一为真）→ 不滚动（`rich-native-kept`）。
2. **等待**：有界 6s 轮询（200ms）等第一条回复格渲染（SPA 导航 ~1–2s；全量加载更慢——实测发现并据此从 3s 放宽）。
3. **滚动时权威复查**：X 全量加载时视频帖先以海报占位、播放器迟水合（live 实测发现的缺陷）→ 每个 tick 复查焦点格真实媒体（`rich-native-kept-late`）。
4. **条件**：焦点格 ≥60% 视口高、回复可见份额 <50%、用户未滚动（`scrollY ≤ 40`）、路由未变、面板仍在。
5. **一次滚动**：`scrollTo(replyTop − 53px)`，把第一条回复带到右栏顶部；X 吸顶标题栏高度 53px 为常量。
6. **迟到媒体回看**：应用后 15s 内若播放器/投票/卡片迟水合且用户未动（与目标位偏差 ≤4px），一次回滚到焦点格（`late-media-return`）；用户任何滚动即终止。
7. **用户优先**：武装窗口内任何 wheel/keydown/pointerdown/touchmove 取消（与 B3 锚点恢复同一语义）；用户已滚动则不竞争。
8. **审计**：每次决策写入 diagnostics 并在测试钩子下镜像到 `<html data-peek-cf>`（与锚点镜像同模式），CDP 验证可从主世界读取。

原生焦点格全程**不移动、不隐藏、不变异**：一次上滚或任意"定位"按钮（滚动到原生控件）即回到互动区。

## B3 双栏布局验证（真实 X，无 CSS 变更）

| 视口 | 左栏（52%） | 右栏格宽 | 评论优先后 |
|---|---|---|---|
| 1280×800 | 666px | 614px | 回复贴顶（replyTop 53） |
| 1024×768（中途缩放） | 532px（min-width 480 生效前） | 492px | 面板保持，X 自行重排 |

52:48 默认比例下两栏实际可读宽度均 ≥490px（1280 视口），不引入新的 X 内部选择器覆盖；本轮零 CSS 变更。

## B4 返回信息流感知

M1 的 B3 有界恢复未改动。comments-first 只滚动**详情页**（阅读中），关闭经 `history.back()` 回列表，列表锚点恢复与详情页滚动位置无关（离线测试 C-6/C-8 覆盖拆除时序）。帧级滚动采样见性能报告（T4/锚点段）。

## 用户操作步骤变化

- 简单帖阅读：0 步（评论直接可见，原来需手动滚过一整屏重复内容）。
- 简单帖互动：+1 次上滚或点"定位"按钮（原 0 步；这是方案 C 的代价，换取评论首屏）。
- 富媒体帖：0 步（行为与 M1 完全一致）。
