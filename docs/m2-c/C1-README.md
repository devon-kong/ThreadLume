# Peek C1 双原生页面实验版

**当前版本 0.1.1。入口修复可交付；所测 Ego 窗口的双栏布局 BLOCKED。** 本版与 M1-R、Legacy 独立。两套 X 页面各自管理 React 和媒体，不使用 iframe，不移动或复制原生节点，不主动调用 X 私有接口。

## 使用

1. `npm run build:dual` 输出 `dist-extension-native-dual/`。浏览器扩展管理页「加载已解压的扩展」选择该目录。加载目录的浏览器原生选择器需由用户操作。
2. 更新后刷新 X 页面。信息流/个人时间线普通点击正文或时间链接后，X 先按原生行为导航，C1 随后建立双页。详情页普通点击保持原生行为；直接打开的详情页可点右上角「Peek 双页」，也保留 C1 扩展菜单入口。动作按钮、媒体、作者/外链、修饰键点击、选中文字均不触发自动双页。
3. 若运行时同时提供公开 `tabs.createSplit` / `tabs.unsplit`，创建浏览器分屏；否则创建可见的并排窗口。并排降级要求当前普通窗口至少 1000px 宽，不能是最大化/全屏。固定/分组/已分屏标签页先退出该状态。会检查两窗实际尺寸与位置；浏览器忽略/钳制时拒绝成功、回滚并在页面显示错误。
4. 左页保留 X 原生原帖和媒体；右页尝试一次定位到原帖下方。任意滚轮、触摸、键盘、pointerdown 接管后，不再自动抢滚动；定位最长等待 10 秒，超时提示手动滚动。
5. 「隐藏右页原帖（实验）」默认关闭。开启时只隐藏确认详情 article，保留原生回复框；已定位过的页面开启此开关会回到回复框。关闭开关恢复原帖。它不隐藏 X 的全部导航、推荐或广告，也不限制左页只能看原帖。
6. 「结束双页」保留左页，只关闭仍停留在同帖/同帖媒体子路由的扩展创建右页。右页已导航作别用时解除配对，不关闭。并排模式只在左窗仍保持扩展设置的几何尺寸时恢复原窗口尺寸。

无需 `tabs`、cookies、scripting、DNR、webRequest 权限。仅 storage + X/Twitter host。源码入口 `native-dual-extension/`，隔离构建 `scripts/build-extension-dual.mjs`。`npm run test:dual` 包含构建安全扫描、控制器及实际内容bundle的DOM测试。

## 明确限制

- 双原生页面初期可能存在两个原帖播放器和额外原生请求。隐藏不是阻止加载，也不保证零解码/零带宽。未量化性能、内存、额外请求数量。
- 当前 Ego 为 Chrome152，官方自动 Split API 起点是155；运行时能力检测才决定路径。**现已真实安装 C1 并测试消息、详情按钮和列表点击入口。** 所测 Ego TaskSpace 窗口的 resize 请求被忽略、右窗尺寸被钳制，两窗重叠，因此 0.1.1 会拒绝该布局并恢复；实际 Split View 与同时可见持续播放仍未验收。不能把该受控窗口结果推断为所有浏览器/所有 Ego 窗口都不支持。
- 两页互动状态由 X 自行更新；不承诺点赞/收藏跨页实时同步。本轮没有执行账号写入。
- 隐藏右页 article 仍可能触发虚拟化重新测量；只能说已测视频样本正常折叠/再挂载，不能推及所有 Article、投票、GIF 或回复上下文。
- 内容控制条为实验工具，会占据页面右上区域；不是最终单一 Peek header。Esc 全部交给 X，不用于关闭配对。
- worker 的 session 恢复经过 mock 测试。建立pair中途进程崩溃时安全放弃未完成pair，可能留下已创建的可见页；不会在不确定时强关标签页。
- 手动取消分屏或把tab移出原window后会解除配对。无需强制保持用户原先布局。
- 构建内无旧 page bridge；零主动私有请求结论限定为源码与产物审计，尚无安装后的网络计数。
