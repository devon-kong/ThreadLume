# M2-B2-C1：评论与线程完整性

## 归属口径

Peek C1 不读取 X 的私有会话数据，也不构造回复树。右栏是 X 自己渲染的会话列，Peek 没有把其 `article` 计入“已确认回复”。当前 X DOM 的普通回复格不暴露稳定的父帖 ID 或 `socialContext`；单靠位置、时间链接或 `scrollY` 无法证明父子关系。对没有可见父子证据的条目，状态是 **未知关系**。引用卡按嵌套结构与自己的点击路由识别，不能当作直接回复。

这一区分有真实必要性：`ruanyf/status/2100757389112938573` 的右侧深滚列表和 `wlzh` Article 返回页中都观察到 X 自身标有“广告”的条目；底部还可能出现推荐。广告在 X 原生 UI 内有标识，Peek 未把它计为回复，但“右侧全是评论”的说法不成立。G6 只能判 **PARTIAL**，后续 C2 的任何排序或计数不能直接遍历右栏所有 `article`。

## 真实回复链

从公开根帖 `2100757389112938573` 进入 `2100789252204490926`，再进入其下一级 `2100882972920672361`：原生列表 DOM 顺序为根→父→焦点；最后一个焦点唯一且其时间链接与 URL 一致。返回两次分别回到父回复详情、根帖详情，路由和焦点随之更新。没有把根帖/父回复误判为引用帖。X 把祖先保留在右侧原生列表的上方，Peek 左卡仅固定焦点；所以祖先**可向上访问，但不与焦点共同位于左栏**，与 Legacy 上下文布局不等价，G7 为 **PARTIAL**。低风险的下一步是提供跳向 X 已渲染祖先的导航提示；不能从 Fiber 或新 GraphQL 请求补造完整祖先链。

`2100882972920672361` 的原生回复按钮显示 0 条回复，因此该分支不能继续提供三级以上后代样本；被删除、不可访问回复、展开深层子回复、引用嵌在评论中的组合均为 **NOT_TESTED**。本轮没有为凑齐这些样本自动发送回复或无限刷新。

## 分页、深滚和候选内容

在 C1 实机受测构建（引用归属修正前）下，高评论样本从右栏 `scrollY≈10` 连续滚到 `≈12259`。脱敏 CDP 记录的三个窗口分别出现 17、17、14 个此前未在当前 DOM 窗口看到的状态 ID；后两个窗口各有 1 个 `TweetDetail` GraphQL 请求，发起脚本来源均为 X 的 `https://abs.twimg.com`。这证明原生列表继续装载可识别条目，也证明这两个请求不是 Peek 自行发起；**不证明所有新增 ID 都是焦点帖的直接回复**。见 `evidence/network-observation-c1.json`、`evidence/conversation-c1.json`。

右栏至少覆盖 5000px；焦点视频在 B2-B 手动场 `scrollY≈5794` 后仍为同一节点且时间推进，C1 性能场 2/2 `sameElement=true`。第二轮 B2-B 与 C1 的深滚视频均由 X 暂停（`playableNow=false`、`currentTime=0`），属于两版本共同观察到的 X 可见性策略，不能报告为“2/2 持续播放”；只确认节点保留，未记录恢复播放结果。未触及评论排序或重排 X 虚拟列表。

加载结束、重复 ID 全量去重、失败重试及真正无回复页的右栏终态没有足够现场证据，状态分别 **NOT_TESTED/PARTIAL**。`kokosn_5656` 投票样本的焦点动作栏计数为 0 只证明计数，不能代替“空评论列表终态”验收。评论里的图片/视频和引用在历史 M2-B1 有原生渲染证据；本轮未对这几类组合逐一复测。原生回复编辑器和回复按钮存在；发送/投票等账号写入没有执行。

## 结果

焦点与路由身份、已渲染的三帖线程顺序、深滚列表继续加载、视频实例保留有有效证据。回复归属、广告/推荐边界的可机器验证性、深层分支与终止态仍不足以判全功能等价；这些差异是进入 C2 时必须先解决的合同边界。
