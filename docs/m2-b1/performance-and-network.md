# M2-B1 性能与网络验收（S5）

统一测量脚本：`docs/m2-b1/evidence/s5-perf.mjs`（三模式同脚本、同浏览器、同账号、同视口、同样本、相近缓存条件）。
样本一致性：三模式打开的详情帖 ID 完全一致（video `2109956494661656931` / photos `2099877465795735861` / text `1760839985715204230`，见各 JSON `openedAt`）。
计时机制：页面内 rAF 轮询条件 + document 捕获期点击监听打时间戳（无 CDP 派发偏差）；每模式 5 轮 × 3 样本。

**诚实边界（先读）**：测量窗口恰逢 X 服务端软限流（多轮高频访问后，部分详情页出现"出错了"与回复加载迟缓）。因此部分轮次样本缺失（已在 JSON `skipped` 中如实记录），**T2（回复进入 DOM）受影响最重**——video 样本在三种模式下回复都未及时加载（t2 全部超时）。以下结论只建立在有数据的样本上，且标注样本量；不声称统计意义上的长期等价。

## T1 原帖首次真实可读（主 Gate：回归 ≤ max(50ms, 基线中位 10%)）

| 样本 | B=M2-B1 lab（n） | C=native（n） | A=M1-R（n） | B vs A |
|---|---|---|---|---|
| video | 1582 (3) | 1577 (4) | 1579 (3) | +3ms |
| photos | 1583 (4) | 1589 (5) | 1577 (2) | +6ms |
| text | 1583 (3) | 1574 (5) | 1588 (4) | −5ms |
| **全部合并中位** | **1583 (10)** | **1577 (14)** | **1582 (9)** | **+1ms** |

原始样本逐值见 `s5-results-*.json`。最慢样本：lab 1615 / native 1650 / m1r 1611——lab 最慢值低于 native 最慢值。
**结论：T1 零回归（+1ms，远小于 50ms 门槛）。** 适配器在导航路径上不做任何事（安装发生在焦点可读之后），这与设计一致。

## T2 第一条真实评论进入 DOM（回归 ≤ max(100ms, 10%)）

受 X 限流影响，只有 photos/text 样本在三模式都有数据：

| 样本 | B=lab | C=native | A=M1-R |
|---|---|---|---|
| photos | 502 (4) | 0 (5) | 0 (2) |
| text | 513 (3) | 0 (5) | 396 (4) |

- **B vs A（Gate 口径）**：photos +502ms、text +117ms——**超过 100ms 门槛，如实判：该窗口内数据不可用于干净对比**。原因：A 的 T1（M1 副本可读）早于 X 原生焦点渲染，t2 轮询起点不同；且 A 的 photos 样本（n=2）恰逢限流恢复初期。此格记录为 INCONCLUSIVE，列入 L4 复测项（方法已就绪：同脚本重跑）。
- **B vs C 的结构性差异**（native t2=0）：lab 模式 t2 ~500ms 的差额发生在 T1 条件满足之后——即焦点已可读后，右栏下一条文本 cell 再出现的时间。受控实验（下）显示深滚帧预算无差异，该 500ms 更可能是适配器 INSTALL→ACTIVE→布局挂载窗口内 X 自己的后续水合延迟，而非持续成本——但它确实是唯一一个可观测的适配器足迹，如实报告。

## T3 原生互动可用 / T4 关闭后信息流恢复

T3 三模式均为 0–1ms（动作栏与编辑器在焦点可读时已可用）。T4 中位：lab 3–6ms / native 0–1ms / m1r 2–5ms（SPA 返回即时恢复；lab 的 +2–5ms 为布局拆卸）。

## 深滚帧预算（受控实验，排除限流噪声）

`s5-scroll-deepdive.mjs`（同窗口同会话背靠背，video 帖）：

| 配置 | 浅滚 0→1500 (10 帧) | 深滚 0→5000 (10 帧) |
|---|---|---|
| 适配器开 + 视频播放中 | 83ms | 80ms |
| 适配器开 + 视频暂停 | — | 77ms |
| 适配器关（原生） | 81ms | 81ms |

**三配置一致（~8ms/帧 @120Hz）。** 早期一轮 harness 出现过 8s 深滚读数，复测证明为测量环境伪影（长跑会话中的页面状态残留），未进入任何结论。

## 包装开销（内部方法 `_getFinalRenderedItems`）

3000 次直测（`out.wrapper`）：
- 包装后（lab）：1.13–1.43μs/调用（总 3.4–4.3ms/3000 次）
- 未包装（native/m1r）：0.23–0.27μs/调用
- **每次调用的包装增量 ≈ 0.9–1.2μs**；X 在深滚时每帧调用该方法的次数为个位数——每帧增加 <10μs，与受控实验"帧预算无差异"互相印证。
- 计数器（合同 stats）：`installs/uninstalls/calls/injections/naturalSightings` 仅聚合计数；采样计时（1/64）仅累加毫秒值；JSON.stringify 断言无正文内容泄漏（C8）。
- 额外 React commit / 重复渲染：焦点条目以同一 key 调和（`entrySnapshot` 在自然可见时持续刷新），S3 深滚实测焦点 cell 数恒为 1、无重复渲染累积；布局无持续漂移（stub 高度稳定 85px）。

## 内存与 Long Tasks

- `performance.memory`（afterPaint/afterScroll 两点采样，逐值在 JSON 中）：三模式趋势一致，无适配模式特有增长。
- Long Tasks：全部会话 0–3 个（总计 ≤4ms），空闲 8s 窗口 **0 long tasks（三模式一致）**——适配器健康检查 interval（1.5s）为微秒级读操作，无可测 CPU 足迹。

## 网络

- **扩展主动私有 API 请求 = 0**：代码级（无 fetch/XHR、无 webpack 探测、无凭据读取——构建期禁止标记扫描 + P3 测试双重覆盖）；适配器与控制器无任何网络调用路径。
- 不捕获凭据、不重放 GraphQL、不扫描内部请求协议、无自动账号写入（本轮全部浏览器操作只读，菜单只开不选）。
- 间接开销观察：适配模式右栏列表与原生相同（同样的 X 自身请求）；焦点保留使焦点 cell 的媒体保持挂载（视频持续解码）——这是产品目标（G5）的固有代价，受控实验显示其不阻塞主线程帧预算。
- **不得从"零扩展主动 GraphQL"推导"平台账号无风险"**：X 侧的限流观察（本轮实测发生）与账号侧风控不由本扩展控制。

## 结论

- T1 Gate：**PASS**（+1ms）。
- T2 Gate：当前窗口数据 **INCONCLUSIVE**（B vs A 无法干净对比；B vs C 存在一次性 ~500ms 的挂载窗口足迹）——列入 L4 复测，不阻塞机制正确性结论。
- 深滚/滚动响应/Long Tasks/内存/包装开销：**无回归**。
