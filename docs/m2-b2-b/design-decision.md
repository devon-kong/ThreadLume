# M2-B2-B — 方案决策（design-decision）

## 结论

**采用方案 A：浮层式阅读器（floating）。** 方案 B（精致全屏双栏，`flush` 变体）实现完成、实测可用，保留为一行常量切换的回退方案，不作为默认。

## A / B 对照（同代码路径，仅几何常量不同）

| 项目 | A 浮层（选中） | B 全屏双栏 |
|---|---|---|
| 实现 | `SKIN_VARIANT="floating"`：卡片内缩 16px、圆角 16px、阴影、背景幕、栏间 16px 透出背景幕 | `SKIN_VARIANT="flush"`：内缩/间距/圆角=0、无背景幕、保留 1px 分隔线 |
| 原生视频/全屏 | 不受影响（S3 实测：自动播放/暂停/恢复/全屏进出/深滚 5000px 同元素存活） | 同（共用机制） |
| 图片灯箱 | 在皮肤之上打开，Esc 只关灯箱（S3 实测） | 同 |
| 原生菜单/HoverCard | `#layers` 传送门，位于视口内、层级最高（S3 实测） | 同 |
| 评论分页 | 不受影响（cell 宽度为安装时恒定常量） | 同 |
| 两栏独立滚动 | 保留（左卡 fixed 自滚 + window 滚动右栏） | 同 |
| 即时预览 | 保留，且**与接管后卡片逐像素连续**（9 次采样 dx/dy/dw 全 0） | 同（同一几何源，差值=0） |
| 原生接管跳动 | 无（T1c：dup/blank/leftover 全 0，文字 dy=0） | 无 |
| 私有 API | 零新增（构建扫描 + 离线测试 + 资源桶核实） | 零新增 |
| 性能 | 配对口径 T1a −0.5ms、T1b −13.5ms、T2b −468.5ms、T4a −14.7ms、T4b −198.3ms | 同机制；视觉层样式少 6 条声明（无实测差异） |
| 视觉 | 浮卡 + 暗背景幕 + 紧凑顶栏，接近原版 Peek 的"阅读焦点"质感；用户偏好 | 干净但贴近原生 X 详情，无浮层质感 |
| 风险 | 已实测通过：cell 底色随主题、应用栏标记隐藏、无承接 React 生命周期问题 | 更低（样式更少） |

对照截图：`evidence/shots/viewport-1440x900.png`（A）与 `evidence/shots/variantB-flush.png`（B）。

## 为什么选 A

1. **用户明确偏好浮层视觉**，且 S1 未发现任何结构性风险：全部通过纯 CSS 覆盖 + 扩展自有节点（背景幕/顶栏）完成，React 节点零移动、虚拟器测量零变化；
2. **稳定性重验证通过**：S3 14/14 场景 + S4 配对性能（无退化，多数指标更快）；
3. B 的"更可靠"只体现在样式声明更少，而 A 的全部风险点（裁剪、层叠、生命周期）均已逐项实测通过，无回退必要。

## 浮层的真实含义（如实说明）

本轮实现的是**单页面原生 React 阅读器的浮层式视觉**：背景幕是暗化的当前页面（已导航后的 X 详情页），**不是**可交互的独立后台时间线，也不伪造时间线内容。关闭入口为顶栏安全返回（或"原生视图"原地还原 X 单栏），与 Legacy 阅读器的"不导航浮层"是不同架构。

## 若未来必须回退

改 `reader-skin.js` 的 `SKIN_VARIANT` 为 `"flush"` 并重建即可；`LAYOUT_CSS` 功能基线（L4 验证过的边到边双栏）始终原样保留，删除皮肤模块本身也不影响阅读功能（`mountSkin()` 失败自动回退）。
